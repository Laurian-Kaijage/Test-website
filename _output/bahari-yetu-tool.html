Bahari Yetu Reporting Tool

A monitoring, evaluation and analysis system for coastal field data in Tanzania — built in R, from field workbook to decision-ready map.

Five field teams, two islands, 25,000 photographs of the seabed — and one set of numbers everyone can agree on

The problem

Marine field data does not arrive tidy. It arrives as workbooks: one per site, per team, per day. A line intercept transect in one format, fish counts in another, invertebrates in a third, and a georeferencing tool writing one row per photograph with its GPS fix.

By the middle of the 2026 survey season the Bahari Yetu programme had field data from twenty sites across Unguja and Pemba, held in more than eighty workbooks. Every report asked the same questions — how many sites have we surveyed, how much reef did we cover, what is the coral cover at each site — and every report answered them slightly differently, because every answer was recalculated by hand.

The tool exists to end that. One pipeline computes each number once; everything else reads it.

What it does

25,019 photographs of the seabed read from the field logs, with their positions

85 R scripts: readers, analysis, and the application itself

20 survey sites, each with its own stations and transects

6 data types — benthic cover, fish, invertebrates, threats, recruits, photoquadrats

A analyst or a programme manager opens one application and finds:

  • Survey progress — sites and stations surveyed, distance of seabed covered, photographs collected and how many of them carry a GPS position.
  • Maps — every survey site, the photoquadrat tracks by habitat, reef extents, and management zones, on satellite or bathymetric basemaps.
  • Analysis panels — benthic cover, reef fish, invertebrates, threats and coral recruitment, each reported per site, per region and per management zone.
  • A quality-control workbook that fills itself from the field data and opens in Excel, so partners who do not use the application still get the same figures.

How it is built

Three layers, and one rule that keeps them honest: the pipeline computes, the data folder holds the result, the application only reads. No figure is calculated twice, and no panel invents a number that a script did not write down.

Built in R: Shiny and bslib for the interface, Leaflet and sf for the maps, dplyr and tidyr throughout, Quarto for the generated reports, and openxlsx where a deliverable has to be a spreadsheet someone can open in Excel.

Three decisions worth explaining

Blank is not zero

A threat nobody ticked is not recorded, not absent. Crown-of-thorns starfish counted before the form had a column for them is not assessed, not zero. Filling those gaps with zeros would turn a measurement that was never made into a finding — and the invented number looks exactly like a measured one.

Data integrity

One place decides what a name means

The same reef is written five ways across the data streams. A single master list holds every spelling, and one function resolves a name to a site code. A spelling it does not know is reported, never guessed — and if the list ever contradicts itself, the pipeline refuses to run.

Reproducibility

Read only what changed

Re-reading every workbook on each run took minutes. Each file’s parsed result is cached against its size, its modification time, and a hash of the reading code itself — so adding one survey log reads one file, and changing how a file is parsed re-reads everything exactly once.

Performance

What it changed

  • One number, one owner. Survey effort, cover, density and recruitment each come from one script, so a figure in a report and a figure on a map cannot disagree.
  • The tracker maintains itself. Station counts, survey dates and transect totals are written into the project workbook from the field data, while anything typed by a person is never overwritten.
  • Problems surface instead of hiding. Every script ends with its own quality checks: duplicate transects, sheets copied between sites, positions that jump, names missing from the master list. The checks report; they never quietly repair.
  • Partners are not locked out. The QC workbook carries the same figures into Excel, with its own legend and a dated history.
